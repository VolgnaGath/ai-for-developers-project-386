# Когда мокать

Мокай только на **границах системы**:

- Внешние API (платёжные, почтовые и т.д.)
- БД (иногда — лучше тестовая БД)
- Время / случайность
- Файловая система (иногда)

Не мокай:

- Свои классы и модули
- Внутренних коллабораторов
- Всё, что под твоим контролем

## Проектирование под мокаемость

На границах системы проектируй интерфейсы, которые легко мокать:

**1. Внедрение зависимостей**

Передавай внешние зависимости аргументами, а не создавай их внутри:

```typescript
// Легко мокать
function processPayment(order, paymentClient) {
  return paymentClient.charge(order.total);
}

// Сложно мокать
function processPayment(order) {
  const client = new StripeClient(process.env.STRIPE_KEY);
  return client.charge(order.total);
}
```

**2. Предпочитай SDK-подобные интерфейсы универсальным fetcher'ам**

Создавай отдельные функции для каждой внешней операции вместо одной универсальной с условной логикой:

```typescript
// ХОРОШО: каждая функция мокается независимо
const api = {
  getUser: (id) => fetch(`/users/${id}`),
  getBookings: (userId) => fetch(`/users/${userId}/bookings`),
  createBooking: (data) => fetch('/bookings', { method: 'POST', body: data }),
};

// ПЛОХО: мок требует условной логики внутри
const api = {
  fetch: (endpoint, options) => fetch(endpoint, options),
};
```

Подход с SDK означает:

- Каждый мок возвращает одну конкретную форму
- Нет условной логики в настройке теста
- Проще видеть, какие эндпоинты задействует тест
- Тайп-безопасность на каждый эндпоинт
